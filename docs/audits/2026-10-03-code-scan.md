# GitHub 后端代码扫描审查 — 2026-10-03

## 结论

本轮对 28 个框架对应的真实 GitHub 仓库检出执行了静态扫描，固定了仓库 URL 和 commit。**尚不满足所有语言/框架完整精准的发布标准。** OAS 校验通过只证明文档结构合法，不证明 API 无遗漏或参数正确。表中的“部分”仅是扫描器发现的 schema 缺口下界；0 不意味着人工核验全部字段正确。

没有运行下载仓库中的应用、安装脚本或测试；没有向 AI 服务发送仓库源码。真实项目扫描与本地回归测试分开统计。

## 修复

- Fastify 同状态响应分支保留 anyOf；识别 reply.status；避免把嵌套调用误提取为参数；支持字面量方括号参数；all 展开为支持的 HTTP 方法。
- 保留有正文的重定向响应；识别响应对象内的未知字段，不能再因为外层是 object 就标成完整。
- 增量指纹覆盖参数、请求体、响应与递归引用的 DTO。无关组件变化不触发接口变更。
- AI 仅填已知缺口，不能覆盖静态类型；响应分支不再被任意 AI 建议替换。单条 AI 失败保留静态结果，并限制并发为4。
- 转换校验器异常返回无效；Electron worker 不再把转换成功等同于文档有效；AI 缓存隔离服务端/模型，超时包含响应正文读取。
- Starlette 支持真实 CRUD 示例中的 @app.route、同文件命名 routes 列表和路径类型转换器；提取 JSONResponse 字面量字段，动态字段保留未知。
- 已识别框架却零路由、Spring 继承未提取映射均显式报告未解析。
- 扫描弹窗先选目录再确认扫描；语言分组只用于浏览框架，不改变自动检测范围。异步过期结果丢弃；更新绑定扫描文档，并检查合并期间的并发编辑。

## 源码证据与发布阻塞

1. Fastify RealWorld：index.js 使用 require('fastify')(...), lib/server.js 使用链式 register 和 @fastify/autoload，路由使用 options.prefix。当前不能安全推导完整挂载路径，输出零路由且未解析。不得将其当成空 API 应用。
2. Spring Petclinic：pom.xml 配置生成 API interfaces，控制器 implements OwnersApi/PetsApi 等，映射在未生成的源码中。现有 OAS 文件可以作为基准，但不能冒充扫描当前实现所得的结果。
3. Starlette CRUD：app.py 的 9 个 @app.route 路由已提取；数据库返回的动态结构仍未知。新增回归校验 PUT 路由、整数路径参数、202 状态与 updated:boolean 字段。
4. weakly typed 返回值、跨文件 DTO、序列化器、全局中间件错误响应，仍需逐字段基准与真实应用契约测试；本轮没有据此宣称“参数完整”。
5. 大型 examples/tests 仓库需要按可部署应用划分扫描入口；直接聚合会碰到 method/path 相同但属于不同应用的操作。
